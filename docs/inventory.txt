## 🧱 1. Create Schema

```sql
CREATE SCHEMA IF NOT EXISTS inventory;
```

---

## 🧩 2. Core Concept

Inventory revolves around **items** and their **movement**.
Every time you buy, sell, manufacture, or adjust stock, the system records a *movement* that affects both:

* **Quantity on hand**, and
* **Value** (linked to the GL).

So we’ll have:

| Table                       | Description                                  |
| --------------------------- | -------------------------------------------- |
| `inventory.items`           | Item master data (products, materials, etc.) |
| `inventory.item_categories` | Optional classification                      |
| `inventory.warehouses`      | Physical or logical storage locations        |
| `inventory.batches`         | Batch or lot control (optional)              |
| `inventory.movements`       | Tracks all stock-ins and stock-outs          |
| `inventory.adjustments`     | Manual inventory corrections                 |
| `inventory.item_valuation`  | Valuation entries tied to GL                 |

## 🧮 3. Table Definitions

### **1. Item Categories**

```sql
CREATE TABLE inventory.item_categories (
    id BIGSERIAL PRIMARY KEY,
    code TEXT UNIQUE NOT NULL,
    name TEXT NOT NULL,
    description TEXT,
    created_at TIMESTAMP DEFAULT now(),
    updated_at TIMESTAMP DEFAULT now()
);
```

---

### **2. Items**

```sql
CREATE TABLE inventory.items (
    id BIGSERIAL PRIMARY KEY,
    sku TEXT UNIQUE NOT NULL,                  -- e.g. "ITEM-001"
    name TEXT NOT NULL,
    category_id BIGINT REFERENCES inventory.item_categories(id),
    description TEXT,
    unit TEXT DEFAULT 'pcs',                   -- Units of measure
    cost_price NUMERIC(18,2) DEFAULT 0,        -- Average or standard cost
    selling_price NUMERIC(18,2) DEFAULT 0,
    track_quantity BOOLEAN DEFAULT TRUE,
    quantity_on_hand NUMERIC(18,4) DEFAULT 0,
    reorder_level NUMERIC(18,4) DEFAULT 0,
    asset_account TEXT DEFAULT '1.3.1',        -- e.g., Inventory (Asset)
    cogs_account TEXT DEFAULT '5.2.1',         -- Cost of Goods Sold
    income_account TEXT DEFAULT '4.1.1',       -- Sales Revenue
    status TEXT DEFAULT 'Active',
    created_at TIMESTAMP DEFAULT now(),
    updated_at TIMESTAMP DEFAULT now()
);
```

---

### **3. Warehouses**

```sql
CREATE TABLE inventory.warehouses (
    id BIGSERIAL PRIMARY KEY,
    code TEXT UNIQUE NOT NULL,
    name TEXT NOT NULL,
    location TEXT,
    description TEXT,
    created_at TIMESTAMP DEFAULT now()
);
```

---

### **4. Movements (the transaction log of stock)**

Every inflow and outflow of inventory is logged here.
This is your *audit trail* and feeds cost accounting and valuation.

```sql
CREATE TABLE inventory.movements (
    id BIGSERIAL PRIMARY KEY,
    item_id BIGINT NOT NULL REFERENCES inventory.items(id),
    warehouse_id BIGINT REFERENCES inventory.warehouses(id),
    movement_date TIMESTAMP DEFAULT now(),
    reference_type TEXT,                         -- e.g., 'Purchase', 'Sale', 'Adjustment'
    reference_id BIGINT,                         -- e.g., Bill ID, Invoice ID
    quantity NUMERIC(18,4) NOT NULL,
    unit_cost NUMERIC(18,4) DEFAULT 0,
    total_cost NUMERIC(18,2) GENERATED ALWAYS AS (quantity * unit_cost) STORED,
    direction TEXT CHECK (direction IN ('IN', 'OUT')),
    gl_transaction_id BIGINT REFERENCES accounting.transactions(id),
    created_at TIMESTAMP DEFAULT now()
);
```

---

### **5. Adjustments**

For physical count or manual corrections.

```sql
CREATE TABLE inventory.adjustments (
    id BIGSERIAL PRIMARY KEY,
    adjustment_number TEXT UNIQUE NOT NULL,
    adjustment_date DATE NOT NULL,
    warehouse_id BIGINT REFERENCES inventory.warehouses(id),
    item_id BIGINT REFERENCES inventory.items(id),
    old_quantity NUMERIC(18,4) DEFAULT 0,
    new_quantity NUMERIC(18,4) NOT NULL,
    difference NUMERIC(18,4) GENERATED ALWAYS AS (new_quantity - old_quantity) STORED,
    reason TEXT,
    posted BOOLEAN DEFAULT FALSE,
    gl_transaction_id BIGINT REFERENCES accounting.transactions(id),
    created_at TIMESTAMP DEFAULT now()
);
```

---

### **6. Item Valuation (GL tie-in)**

This logs financial value changes of stock.
It keeps your **inventory asset account** in sync with **COGS** and **revenue**.

```sql
CREATE TABLE inventory.item_valuation (
    id BIGSERIAL PRIMARY KEY,
    item_id BIGINT NOT NULL REFERENCES inventory.items(id),
    movement_id BIGINT REFERENCES inventory.movements(id),
    valuation_date TIMESTAMP DEFAULT now(),
    debit_account TEXT,                          -- e.g., Inventory
    credit_account TEXT,                         -- e.g., Accounts Payable or COGS
    amount NUMERIC(18,2) NOT NULL,
    gl_transaction_id BIGINT REFERENCES accounting.transactions(id),
    description TEXT
);
```

## ⚙️ 4. Posting Functions (Integrating with GL)

### **A. Post Purchase (Stock Inflow)**

When goods arrive:

> Debit Inventory
> Credit Accounts Payable

```sql
CREATE OR REPLACE FUNCTION inventory.post_purchase(
    p_item_id BIGINT,
    p_quantity NUMERIC,
    p_unit_cost NUMERIC,
    p_reference_type TEXT,
    p_reference_id BIGINT,
    p_user BIGINT
)
RETURNS VOID AS $$
DECLARE
    v_item inventory.items%ROWTYPE;
    v_total NUMERIC(18,2);
    v_lines JSONB;
BEGIN
    SELECT * INTO v_item FROM inventory.items WHERE id = p_item_id;
    v_total := p_quantity * p_unit_cost;

    INSERT INTO inventory.movements (item_id, quantity, unit_cost, direction, reference_type, reference_id)
    VALUES (p_item_id, p_quantity, p_unit_cost, 'IN', p_reference_type, p_reference_id)
    RETURNING id INTO STRICT p_reference_id;

    v_lines := jsonb_build_array(
        jsonb_build_object('account_ref', v_item.asset_account, 'debit', v_total, 'credit', 0, 'memo', 'Stock In'),
        jsonb_build_object('account_ref', '2.1.1', 'debit', 0, 'credit', v_total, 'memo', 'Accounts Payable')
    );

    INSERT INTO inventory.item_valuation (item_id, movement_id, debit_account, credit_account, amount)
    VALUES (p_item_id, p_reference_id, v_item.asset_account, '2.1.1', v_total);

    PERFORM accounting.post_transaction(
        now(),
        'INV-PUR-' || p_reference_id,
        'Inventory Purchase',
        p_user,
        'inventory_purchase',
        v_lines
    );

    UPDATE inventory.items
    SET quantity_on_hand = quantity_on_hand + p_quantity,
        cost_price = ((cost_price * quantity_on_hand) + v_total) / (quantity_on_hand + p_quantity)
    WHERE id = p_item_id;
END;
$$ LANGUAGE plpgsql;
```

---

### **B. Post Sale (Stock Outflow)**

When goods are sold:

> Debit Cost of Goods Sold
> Credit Inventory

```sql
CREATE OR REPLACE FUNCTION inventory.post_sale(
    p_item_id BIGINT,
    p_quantity NUMERIC,
    p_unit_cost NUMERIC,
    p_reference_type TEXT,
    p_reference_id BIGINT,
    p_user BIGINT
)
RETURNS VOID AS $$
DECLARE
    v_item inventory.items%ROWTYPE;
    v_total NUMERIC(18,2);
    v_lines JSONB;
BEGIN
    SELECT * INTO v_item FROM inventory.items WHERE id = p_item_id;
    v_total := p_quantity * p_unit_cost;

    INSERT INTO inventory.movements (item_id, quantity, unit_cost, direction, reference_type, reference_id)
    VALUES (p_item_id, p_quantity, p_unit_cost, 'OUT', p_reference_type, p_reference_id)
    RETURNING id INTO STRICT p_reference_id;

    v_lines := jsonb_build_array(
        jsonb_build_object('account_ref', v_item.cogs_account, 'debit', v_total, 'credit', 0, 'memo', 'Stock Out'),
        jsonb_build_object('account_ref', v_item.asset_account, 'debit', 0, 'credit', v_total, 'memo', 'Inventory Asset')
    );

    INSERT INTO inventory.item_valuation (item_id, movement_id, debit_account, credit_account, amount)
    VALUES (p_item_id, p_reference_id, v_item.cogs_account, v_item.asset_account, v_total);

    PERFORM accounting.post_transaction(
        now(),
        'INV-SALE-' || p_reference_id,
        'Inventory Sale Posting',
        p_user,
        'inventory_sale',
        v_lines
    );

    UPDATE inventory.items
    SET quantity_on_hand = quantity_on_hand - p_quantity
    WHERE id = p_item_id;
END;
$$ LANGUAGE plpgsql;
```

## 🧾 5. Supporting Views

### **Inventory Summary**

```sql
CREATE OR REPLACE VIEW inventory.item_summary AS
SELECT
    i.id AS item_id,
    i.sku,
    i.name,
    c.name AS category,
    i.unit,
    i.quantity_on_hand,
    i.cost_price,
    (i.quantity_on_hand * i.cost_price) AS inventory_value
FROM inventory.items i
LEFT JOIN inventory.item_categories c ON c.id = i.category_id;
```

---

### **Stock Movement History**

```sql
CREATE OR REPLACE VIEW inventory.movement_history AS
SELECT
    m.id,
    i.name AS item_name,
    m.movement_date,
    m.reference_type,
    m.direction,
    m.quantity,
    m.unit_cost,
    m.total_cost,
    w.name AS warehouse
FROM inventory.movements m
JOIN inventory.items i ON i.id = m.item_id
LEFT JOIN inventory.warehouses w ON w.id = m.warehouse_id
ORDER BY m.movement_date DESC;
```
